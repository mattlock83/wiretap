How coverage is measured

Coverage from your API spec

See the cases your API promises.
Find the ones your tests missed.

Wiretap turns supported spec rules into concrete cases: enum values, optional fields, collection sizes and declared boundaries. Each covered case links to the test and captured exchange that exercised it.

One request or response can cover many cases. JSON coverage keeps their observed combinations together and makes gaps and measurement limits visible.

Read the coverage rules

Spec coverage is evidence of tested cases, not proof that every possible combination or business behavior was tested. Mock responses remain assumptions about their providers.

A few practical details

Fits your tests.
Keeps its promises clear.

Do I need to change my test framework?

No. Jest, Playwright Test and Mocha use a configuration wrapper. Go uses Run in TestMain and StartTest in a test or shared helper. These integrations handle Wiretap startup, cleanup and exports. Plain JavaScript and the HTTP API support custom harnesses. Your framework owns the tests and assertions.

Does my application need Wiretap-specific code?

Configure your test environment's URLs so traffic passes through Wiretap. For parallel tests sharing one application, reuse working OpenTelemetry/W3C trace propagation. Without it, run sequentially or isolate workers. There is no Wiretap-specific ID to propagate through the application.

Do I need a spec?

HTTP APIs use OpenAPI; an individual HTTP API can explicitly opt out with unknown contract coverage. Native gRPC requires Protobuf descriptors, obtained by reflection or supplied locally. Native gRPC coverage includes methods and supported field cases such as enums, presence and collections across unary and streaming calls. Unevaluated validation annotations remain visible as measurement limits.

Can I check my mocks against provider tests?

Use wiretap check consumer with both complete archives and their Postman collections. Every selected mock request needs a compatible response from the provider's passing tests; uncovered scenarios fail. Use wiretap check provider from the provider's viewpoint. This checks concrete examples, not every possible value or a live deployment. Read the checking guide.

What data should I use?

Use isolated test environments with synthetic data and dummy secrets. Wiretap retains the traffic you send, including payloads and credentials. Captured traffic is retained unchanged.

Try the Go example
git clone https://github.com/mattlock83/wiretap.git
cd wiretap
go build -o dist/wiretap ./cmd/wiretap
WIRETAP_BINARY="$PWD/dist/wiretap" go -C examples/go-suite test -count=1 ./...

Requires Go 1.26+. Commands shown for macOS/Linux; see the example guide for Windows.
